latexally Guide

latexally converts homework, discussion, and exam sources into PDFs a screen reader can navigate: real headings, spoken math, described figures, and contrast-safe colours. Your .tex stays untouched by default.

$ cd questionBank/fa26/hw/9
$ latexally run

Press Enter through each screen, then b to build. The PDF lands in the same folder.

Tutorial

Your first accessible PDF

One homework folder, start to finish. About ten minutes the first time, most of it installing TeX.

Setup

  1. Clone the tool next to questionBank/. The shipped profiles find the course sources at ../../questionBank, relative to profiles/.

    
├── EECS16A-Accessibility-Tool/
└── questionBank/

  2. Install TeX and the tagging packages:

    $ brew install --cask mactex-no-gui
$ sudo tlmgr install tagpdf pdfmanagement-testphase latex-lab latexmk

  3. Install latexally with all extras, from the clone:

    $ cd EECS16A-Accessibility-Tool
$ uv tool install --editable '.[all]'

    Keep --editable: the tool reads profiles/ from the clone.

  4. Build the spoken-math driver (needs Rust's cargo):

    $ git submodule update --init
$ cd mathspeech-driver && cargo build --release

    Without it, every formula builds silent, and the build reports no error.

  5. Verify the toolchain:

    $ latexally -p ee66 doctor

    Look for Tagging mode: modern on the last line. A veraPDF warning is fine.

First run

Where you run it is the scope. Stand in the assignment folder:

$ cd ../questionBank/fa26/hw/9
$ latexally run

The runner opens full-screen. Each screen has a sensible default, so Enter alone gets you a good build.

Undo

revert deletes what a run produced and restores any .tex it rewrote, using git. It previews first:

$ latexally -p ee66 revert          # preview
$ latexally -p ee66 revert --write  # do it

clean deletes output only. Both keep worklogs with written descriptions unless you add --force.

How-to guides

Tuning it to your course

Two files carry every setting. The profile (profiles/<course>.yaml) holds course facts and style. run.yaml holds one run's choices.

New course

  1. Copy a shipped profile:

    $ cp profiles/eecs16a.yaml profiles/ee120.yaml

  2. Edit the identity and corpus keys:

    name: ee120
course:
  number: "EE 120"
  name: "Signals and Systems"
  language: en-US
corpus:
  root: "../../ee120-materials"   # relative to this file

  3. Verify, then use it:

    $ latexally -p ee120 doctor
$ latexally -p ee120 run
course.number
Labels the course in the runner's course picker
course.name
Same. Neither appears in the PDF.
course.language
PDF language tag, which screen readers use to pick a voice
default: true
Makes latexally run start on this course. Set it in one profile only.

The PDF title comes from each document's own \title.

Typos are silent. The loader ignores keys it doesn't know. Check spelling against Profile keys.

Every command except run needs -p while several profiles are installed. Save typing with an alias:

$ alias latexally='latexally -p ee120'

More: corpus.scopes, variants, and kinds in Profile keys.

Vector and notation style

Notation is a list of rewrite rules under notation: in the profile. Each rule finds one form inside math and names its replacement. EE 66 ships bold vectors:

notation:
  - id: bold-vector
    message: "vectors are bold, not arrowed"
    macro: [vec, overrightarrow]
    to: '\mathbf{{arg}}'

Rule fields

id
Rule name. Findings report as ALLY-FMT-<id>.
macro
Macro name or list, matching \name{arg} or \name x
pattern
Python regex instead of macro. Use exactly one of the two.
to
Replacement. {arg} is the macro argument; \1…\9 are regex groups.
parenthesize
true wraps a non-atomic argument in ( ). Default false.
fix
false reports without rewriting. Default true.
message
Text shown with each finding

Keep to and pattern in single quotes, so backslashes survive YAML.

Arrowed vectors instead

  - id: arrow-vector
    message: "vectors are arrowed"
    macro: mathbf
    to: '\vec{{arg}}'
Scope check. This rule also rewrites bold matrices such as \mathbf{A}. Preview before building.

Report only

  - {id: vec-report, macro: vec, to: '\mathbf{{arg}}', fix: false}

Where rules apply

WhereEffect
latexally run / buildRewrites the converted copy. Sources untouched.
latexally -p ee66 checkLists each departure as a warning
latexally -p ee66 notation --show-diffPreviews a permanent source rewrite
latexally -p ee66 notation --writeRewrites your .tex. Needs a clean git tree.
f in the runnerSame rewrite, confirmed with y

Rules touch math only: $…$, \[…\], \(…\), and display environments. Comments and verbatim are skipped.

Matrix alignment

math:
  matrix_align: r   # l, c, r, or empty for LaTeX's centred default

This adds one preamble line at build time. Starred bmatrix* keeps its own alignment.

Colours

Coloured text must reach 4.5:1 contrast against white. The colours screen shows each course colour, its contrast, and its replacement.

ModeBehaviour
palette (default)Remaps every course colour onto latexally's shared accessible palette
conformingDarkens each failing colour just enough to pass. Passing colours stay as written.
houseKeeps course colours unchanged, contrast failures included

On that screen, k keeps a colour's original, u undoes that, and e sets a custom hex. Choices save to run.yaml:

colors:
  mode: palette
  overrides: {solutionColor: '#187AC4'}

To register a course colour, add it to the profile's colors.originals as name: "#RRGGBB".

Figure descriptions

A screen reader announces a figure by its description. The runner's figures screen picks how undescribed figures are handled:

ChoiceEffect
caption (default)Adds a visible \caption{<<TODO:figure-id>>} to floats that lack one
on (placeholders)Marks <<TODO:figure-id>> in the converted source, and lists each figure in a worklog
offSkips figures. Tagging, headings, and math still run.

Writing descriptions

  1. List the figures in scope. From the assignment folder:

    $ latexally -p ee66 scan

    This writes a worklog such as questionBank/ally-out/descriptions/fa26/hw_fig_alt_texts.yaml. The most-used figures come first.

  2. Fill in each alt_text. Leave the id and at alone.

    fig-3870069f66da:
  at: fa26/hw/9/questions/q_divider.tex:14
  alt_text: Voltage divider. A 5 V source drives 1 kΩ and 2 kΩ resistors in series; the output is across the 2 kΩ.

  3. Check progress, then rebuild with latexally run:

    $ latexally -p ee66 figures

Each id is content-addressed, so one description covers every assignment that reuses the figure. To write descriptions into the .tex permanently, run latexally -p ee66 apply --write.

Good descriptions

  • Plain words: no $, backslashes, or braces.
  • Skip "image of", the caption, and the filename.
  • Convey the data, not the drawing. Don't rely on colour alone.
  • About one sentence, 200 characters or fewer.
  • Don't give away the answer.

The test: cover the figure, read only your description, and answer the question.

Mark purely decorative images (banners, logos) in the profile's figures.artifact_allowlist.

More: all ten rules, genre templates for circuits and plots, and table markup in ALT_TEXT_SPEC.md.

Replay a run

Rebuild many assignments, or rebuild in CI, without the runner.

  1. Press s in the runner. It saves questionBank/ally-out/run.yaml.

  2. Replay it, from the questionBank/ folder:

    $ latexally -p ee66 build --config ally-out/run.yaml --write

A saved file looks like this. Edit assignments to build more.

profile: ee66
assignments:
- fa26/hw/9
standards:
  tagging: true
  retrofit: true
  bookmarks: true
  question_tags: true
  math_speech: true
  unicode_map: true
colors:
  mode: palette
  overrides: {}
alt:
  mode: caption
  strict: false
output:
  root: ally-out
  write_mode: in-place
  keep_pdf: true
  keep_logs: true
  keep_tex: true
  paths: {}
variants: []
baseline: false
jobs: 1

Without --write, build is a dry run. The file never stores write. To reopen it in the runner, use latexally run --config ally-out/run.yaml.

Hand-written files. Missing keys get older defaults: conforming colours, worklog figures, and mirror output. Start from a saved file.

Checking a PDF

Validate a built PDF's structure: tags, figure and formula alt text, headings, title, language, and bookmarks.

$ latexally -p ee66 check --pdf fa26-hw-9-solution-accessible.pdf

Hear it the way a student would, as Canvas Ally renders it:

$ latexally -p ee66 formats fa26-hw-9-solution-accessible.pdf

formats writes text transcripts, an MP3, and a braille file to formats/<name>/ beside the PDF. It needs extra tools:

$ brew install poppler liblouis ghostscript ffmpeg openjdk
$ ./vendor/pdfbox/fetch.sh    # from the tool clone
